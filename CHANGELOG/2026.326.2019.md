# 2026.326.2019 — revert(kde-shell): declare kdotool under aur: again, now that the builder installs it

## Summary

Reverts the workaround from opencharly/layer-kde-shell#8. That change downloaded `kdotool` 0.3.0's release tarball because the `aur:` builder silently dropped the package; the unified builder mechanism has since landed and shipped (opencharly/sdk#608, released as sdk `v0.2026326.825` and charly `v2026.326.1922`), so the layer goes back to declaring what it needs:

```yaml
aur:
    package:
        - kdotool
```

- the workaround's **two `run:` steps are deleted in the same cutover**, exactly: `kde-shell-kdotool-download` (its `download:` URL, `to: /tmp/kdotool`, `extract: tar.gz`, and the long comment explaining why an `aur:` declaration could not be used) and `kde-shell-kdotool-install` (its `command:` — `install -Dm755 … /usr/bin/kdotool` and `test -x` — with `run_as: root`), together with their check ids and the download's staging path. Nothing else in the file changes except the declaration below. (The workaround had **no checksum verification** — the step fetched a URL and extracted it; the body does not imply otherwise. The AUR route installs through pacman, which verifies against the package database.);
- the declaration is honoured because a candy's `distro.<tag>.aur` section reaches any image whose tag chain selects the tag, routed by the caller's builder map (`aur: arch.arch-builder`), and the builder's reply carries the package into the image;
- an image whose builder cannot run now **fails the build naming the candy** instead of shipping without the package — the behaviour whose absence is what #8 had to work around.
