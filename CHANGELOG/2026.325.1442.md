# 2026.325.1442 — fix(kde-shell): install kdotool from its pinned release, not a silent AUR skip

## Summary

Closes opencharly/layer-kde-shell#7. `kdotool` was declared under `aur:` and **never installed** — the build exits 0 and the layer'"'"'s own check then fails.

**Root cause.** AUR packages are served by an **externalized detection builder** (sdk `render_prep`: "for each matching candy an EXTERNALIZED detection builder (pixi/npm/aur) … the COPY lines come from the plugin"). When that builder does not run for the image, the packages are dropped silently. Measured on `quay.io/archlinux` **and** `docker.io/cachyos/cachyos-v3`: no `/usr/bin/kdotool`, build green, check red.

**Fix.** kdotool 0.3.0 ships a prebuilt x86_64 binary, so the layer downloads that pinned release tarball and installs it in its own plan:

- `download:` the pinned `kdotool-0.3.0-x86_64-unknown-linux-gnu.tar.gz`, `extract: tar.gz`;
- `install -Dm755 … /usr/bin/kdotool` followed by `test -x` — so a missing binary fails the **build**, not only a later check.

No AUR helper, no cargo toolchain, and nothing that can be skipped without a red build.

| file | change |
|---|---|
| `charly.yml` | the `aur:` stanza removed; two plan steps added (download, install+assert) |
